FIELD GUIDE / TYPOGRAPHY SYSTEMS

A practical guide to better type systems.

A typography system is a set of deliberate decisions about size, hierarchy, spacing and typeface roles. This guide explains the decisions behind a modular scale and how to test them before shipping.

1. Start with a readable base size

Choose a body text size that suits the reading context. 16px is a useful web starting point, not a universal rule. Dense interfaces may need a different rhythm from long-form editorial content. Test actual paragraphs, labels and controls rather than judging numbers in isolation.

2. Choose a scale ratio

A modular scale multiplies a base size by a consistent ratio. Smaller ratios such as 1.125 or 1.2 create restrained hierarchies. Ratios around 1.25 and 1.333 create more visible heading contrast. Larger ratios can suit expressive display typography, but may create awkward jumps in compact layouts.

Compare common scale ratios or generate a modular type scale.

3. Make typography fluid

Responsive type can interpolate between a minimum and maximum size as the viewport changes. CSS clamp() expresses the minimum, preferred fluid value and maximum. Keep the viewport range explicit and test the result at narrow, intermediate and wide widths. Fluid growth should not make body text uncomfortable or headings overflow.

4. Pair display and body fonts

Use contrast with purpose. A display serif can add editorial character while a neutral sans-serif keeps paragraphs readable. Two related sans-serifs can feel cohesive in product interfaces. Compare x-height, weight range, letter width and punctuation—not just the mood of the specimen.

Explore the font pairing library in the interactive canvas, then adjust headline size, line-height and text measure with real copy.

5. Define semantic roles

Do not let raw size values become your only design language. Give tokens roles such as display, heading, body, label and caption. Semantic names make it easier to maintain a system when the underlying scale changes. Check that heading levels follow a logical document hierarchy.

6. Export and maintain tokens

Share a consistent source of truth between design and code. Type Scale Studio exports CSS custom properties, fluid CSS, JSON, Tailwind configuration, SCSS variables and a Tokens Studio-style JSON structure for Figma workflows. Review the generated output in your own toolchain before production use.

Review typography tokens and manage and share project presets.

7. Check accessibility and real content

  • Keep body text comfortably readable and allow browser zoom.
  • Use sufficient line-height and a readable line length.
  • Do not communicate hierarchy through size or color alone.
  • Preserve semantic heading order and visible keyboard focus.
  • Test long words, translated content and small screens.
  • Respect reduced-motion preferences and user font scaling.

Frequently asked questions

What is the best typography scale ratio?

There is no universal best ratio. 1.2–1.25 is a flexible starting range for many interfaces. Choose based on content density and test in context.

Should all font sizes be fluid?

No. Fluid sizing is most useful for selected display and heading roles. Fixed or bounded sizes may be more appropriate for controls, labels and dense data.

Can I use exported Figma tokens directly?

The Figma export is structured for Tokens Studio-style token workflows. Validate naming, token types and import behavior in the plugin version and token setup you use.
